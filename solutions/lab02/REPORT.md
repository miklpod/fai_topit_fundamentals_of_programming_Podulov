### Вопросы для анализа

1. Чем поверхностная копия отличается от глубокой?

При поверхностной копии создается новый объект только верхнего уровня, а ссылки на все вложенные списки и их содержимое просто копируются. При глубоком копировании все объекты создаются заново.

2. Почему глубокое копирование не следует применять автоматически ко всем объектам?

Глубокое копирование потребляет много памяти, если объект большой и сложный. При наличии циклических ссылок классическая реализация глубокого копирования уйдет в бесконечную рекурсию,
что вызовет переполнение стека - stack overflow

3. В каких случаях достаточно поверхностной копии?

Поверхностной копии достаточно, если объект не содержит вложенных изменяемых объектов или вообще нужно менять параметры только верхнего уровня.

## Задание 3. Подсчет ссылок и время жизни объекта

Создадим `task_3.py` и импортируем модуль `sys`.

Исследуем изменение счетчика ссылок:

```python
import sys

data = [1, 2, 3]
print("После создания:", sys.getrefcount(data))

alias = data
print("После создания alias:", sys.getrefcount(data))

container = [data]
print("После помещения в контейнер:", sys.getrefcount(data))

del alias
print("После del alias:", sys.getrefcount(data))

container.clear()
print("После очистки контейнера:", sys.getrefcount(data))
```
```
После создания: 2
После создания alias: 3
После помещения в контейнер: 4
После del alias: 3
После очистки контейнера: 2
```
- почему `sys.getrefcount()` показывает на одну временную ссылку больше?

Так как сама передача объекта в качестве аргумента временно создает еще одну ссылку.
- какие инструкции увеличивают счетчик?

    - присваивание объекта новой переменной
    - передача объекта в функцию как аргумент
    - добавление объекта в контейнер(список, множество,словарь, кортеж)
    - само создание объекта
- какие инструкции уменьшают счетчик?

    - явное удаление имени через `del`
    - переприсваивание переменной(-1, но +1 за счет появления нового объекта по этой ссылке)
    - удаление объекта из контейнера
    - уничтожение самого контейнера
- почему `del alias` удаляет имя, а не командует напрямую удалить объект?

Если бы `del` удалял сам объект, то это бы сломало другие переменные, которые на него ссылаются.

Дополним программу экспериментом со слабой ссылкой. Для этого создадим простой класс-контейнер:

```python
import weakref


class Record:
    pass


record = Record()
weak_record = weakref.ref(record)

print(weak_record())
del record
print(weak_record())
```
```
<__main__.Record object at 0x00000247B1D79010>
None
```
Слабая ссылка в Python не продлевает время жизни объекта, потому что она не увеличивает его счетчик ссылок и не мешает уничтожить объект, если на него больше не указывают сильные ссылки.
Слабые ссылки могут пригодиться в ситуациях, когда нам нужно очищать кэш, если мы закончили работу с объектом, чтобы не нагружать память(и не держать там бесполезные объекты вечно).

### Вопросы для анализа

1. При каком условии подсчет ссылок позволяет освободить объект?

Объект освобождается в тот момент, когда у него закончились сильные ссылки (счетчик сильных ссылок равен нулю).

2. Всегда ли освобождение Python-объекта означает немедленный возврат памяти операционной системе?

Нет, освобождение объекта в Python означает, что память возвращается интерпретатору (CPython). Память для объектов в Python поделена на арены, пулы и блоки, если в арене есть хотя бы один существующий
объект, то вся арена закреплена за процессом Python. 

3. Чем сильная ссылка отличается от слабой?

Слабая ссылка не увеличивает счетчик ссылок объекта, который увеличивается и уменьшается только при операциях над сильными ссылками.
Слабые ссылки не влияют на жизнь объекта, а сильные влияют.

### Вопросы для анализа

1. Как возникает циклическая ссылка?

Циклическая ссылка возникает, если в один объект положить ссылку на другой объект, а в другой - ссылку на первый.

2. Почему объект с ненулевым счетчиком ссылок иногда может быть недостижим из программы?

Объект может иметь счётчик > 0, но быть недостижимым, если ссылки на него только из других недостижимых объектов.

3. Зачем сборщик мусора разделяет отслеживаемые объекты по поколениям?

Сборщик мусора разделяет отслеживаемые объекты по поколениям ради повышения производительности,
так как свежие объекты нужно проверять часто, а старые можно реже(молодые объекты умирают чаще).

### Часть 2. Рост списка

Создадим пустой список и добавим в него 100 элементов. Выведем длину и размер списка только в тот момент, когда результат `sys.getsizeof()` изменился.
```python
import sys
k = []
last = sys.getsizeof(k)
print(f"len={len(k)}  size={last}")

for i in range(100):
    k.append(i)
    s = sys.getsizeof(k)
    if s != last:
        print(f"len={len(k)}  size={s}  (+{s - last})")
        last = s
```
